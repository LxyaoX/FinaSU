TEESimulator module bundled with FinaSU
=======================================

The archive in this directory is the TEESimulator flashable module, repacked
with one change: the x86_64 payload and the WebUI self-tests are removed,
because FinaSU ships an arm64-v8a build only.

  Project : https://github.com/JingMatrix/TEESimulator
  Release : canary-75, TEESimulator-v4.0-75-fcf1738-Release.zip
  Build   : v4.0 (75-fcf1738-release), versionCode 75
  Author  : JingMatrix and contributors
  License : GPL-3.0 (see the project's LICENSE)

Everything else is upstream, byte for byte: classes.dex (the control daemon),
arm64-v8a/inject, arm64-v8a/libteesim_*.so, arm64-v8a/teesim-uds, the shell
entry points, module.prop, sepolicy.rule, config.default.json and webroot.

FinaSU does not flash it as a module. The payload is staged under
/data/adb/teesim/runtime, its sepolicy.rule is handed to `ksud sepolicy apply`,
and a post-fs-data.d hook starts the daemon, so nothing appears in the module
list. The module wrapper (module.prop, customize.sh, service.sh, update.json)
and webroot are dropped at that point, because the manager replaces them.
Runtime state (configuration and the keybox) stays in /data/adb/teesim, exactly
as upstream expects.

Corresponding source for this GPL-3.0 binary is available at
https://github.com/JingMatrix/TEESimulator (tag: the commit fcf1738, branch
dev). Rebuilding upstream as-is and flashing the resulting zip produces the
same module apart from the dropped x86_64 files.

No keybox is bundled: it holds private keys and is never redistributed. Until
the user imports one under the TEESimulator settings page, the interceptor
stays inert and every key keeps going to the real hardware.
